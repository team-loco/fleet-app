Fleet architecture

team-loco/fleet-app · Rust 1.99 · gpui-component 0.7 on gpui-pre 0.3.9 · kube-rs 4.2 · as of 2026-10-13

Fleet is a native macOS app that watches many Kubernetes clusters at once, with Flux built in and Loco behind a cargo feature. The UI renders plain data models and sends commands. One backend, live or demo, owns all cluster I/O and pushes snapshots back over a channel. There is no server and no database.

How a change reaches the screen

1 · WatchEach added cluster gets a kube client and lazy reflectors. Nodes and Pods are always watched; other kinds only while their page is open.manager.rs · watch.rs
2 · DebounceObject changes are coalesced per cluster, at most one rebuild every 250 ms.live.rs
3 · AssembleIndexed once per rebuild, then mapped into core models: problems, home, the open page, Flux, Loco.assemble.rs · problems.rs · gitops/
4 · SendA whole Snapshot crosses the channel to the UI thread.Update::Snapshot
5 · RenderThe Store applies it to AppState and gpui redraws the visible views.store.rs · screens/

Actions run in reverse: a click becomes a Command; actions/ patches or execs against the API; the target shows as in progress until the watched object reflects the outcome, or a failure toast explains why.

Flux

  • Flux kinds (HelmRelease, Kustomization, GitRepository, HelmRepository, OCIRepository, HelmChart) are watched dynamically wherever Flux is detected and converted to GitOpsObject.
  • fleet-flux::summary turns each object into one plain sentence and a status. The home page, problems, object pages and grid all read from it.
  • HelmRelease history is decoded from sh.helm.release.v1.* secrets, only while that release's page is open.
  • Changes: one bare git mirror per GitRepository URL and branch, fetched with your own credentials (never Flux's secrets). Each cluster's applied revision is mapped to commits to show per-cluster outcomes.
  • Reconcile, suspend, resume and force are merge patches on Flux annotations or spec.suspend. "Reconciling" holds until lastHandledReconcileAt catches up.

Build, test, ship

  • Every tool is pinned in mise.toml. mise run check runs fmt, clippy -D warnings with and without loco, nextest, typos and cargo-deny.
  • mise run shot -- <screen> [dark|light] renders a screen headlessly; apps/fleet-shots/tests/ui.rs drives clicks and keys in tests.
  • mise run e2e:test runs every live test against two kind clusters with Flux scenarios: a crashlooping release on one cluster only, a missing secret key, suspended and broken objects, a pending pod.
  • mise run bundle / bundle:loco build a signed dist/Fleet.app with the squircle icon and the git sha in fleet --version.
